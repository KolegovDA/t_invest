# ПЛАН ВЕРСИИ 1.3 (черновик требований, записано 26.09.2026)

Статус: требования собраны, к работе не приступали.
Начинается ПОСЛЕ завершения текущих задач v1.2
(авторизация/регистрация клиента, головной сервер + репликация).

Версионность: головной сервер ведётся ОТДЕЛЬНО от клиента
(собственная версия, например head 1.0.x, changelog в этом файле
и в отдельном файле внутри head_server).

## 1. Коммерческая часть — комиссия с прибыли

- Личный кабинет пользователя с балансом (ЛК-баланс).
- После каждой СДЕЛКИ с прибылью списывается % от прибыли
  в пользу сервиса (списание в ЛК-баланс, фиксируется в журнале).
- Процент комиссии определяется НА ГОЛОВНОМ СЕРВЕРЕ:
  * по умолчанию 30%;
  * варианты: 15%;
  * «Без комиссии» — 0%.
- Настройка применяется ПО ПЛАТФОРМЕ (брокеру) для КАЖДОГО
  пользователя отдельно (например: T-Invest 30%, Bybit 15%).
- Открытые вопросы к пользователю при старте задачи:
  * что происходит при отрицательном балансе ЛК (блокировка
    торговли / долг);
  * списывается ли комиссия с нереализованной прибыли или только
    с реализованной после SELL;
  * где пользователь видит ЛК-баланс (только на головном сервере
    или дублируется в клиенте);
  * пополнение ЛК-баланса (кто и как вносит).

## 2. Обновления интерфейса и стратегий через головной сервер

- Публикация обновлений на головном сервере (админка):
  * обновления Web UI клиента (сборка frontend);
  * обновления торговых стратегий (параметры/логика).
- В веб-интерфейсе клиента — кнопка «Обновить»: проверяет
  доступные версии на головном сервере, скачивает и применяет.
- Продумать: версии/совместимость, откат на предыдущую версию,
  целостность (подпись/хэш пакета), что делать с запущенными
  сессиями при обновлении.
- Открытые вопросы: автоприменение или только по кнопке;
  диапазон времени, когда обновлять нельзя (торговые часы).

### 7.1. Сравнение торговой системы со старым ПО

Совпадает (переносить не нужно, уже есть в новой системе):
- спотовая сетка с усреднением: BUY-лимиты ниже рынка,
  SELL-лимит сверху на каждый ордер;
- первый вход после падения ~0.5% + траллинг входа
  (старое: grid_step 0.5% + trall_tp 0.15%; новое:
  first_entry_activation_percent 0.50 + entry_rebound 0.15);
- расчёт ТП с учётом комиссии и «пыли» (мин. лота):
  старая формула динамического ТП через fee 0.2%,
  dust = baseIncrement, min_pure_profit 0.125%;
- сетка строится от исторического минимума (старое: 5 лет
  недельных свечей, минимум x2, целевая просадка 40–70%;
  новое: исторический диапазон свечей + мин. шаг 0.30%);
- восстановление незакрытой сетки после перезапуска
  (старое: sqlite open_grid; новое: state persistence);
- «режим сушки» (старое) = закрытие сеток без новых входов —
  аналог stop/graceful-stop в новой системе.

Отличия (кандидаты на перенос, решить при реализации):
- РЕШЕНО 27.09.2026: досрочное закрытие сетки (прибыль >=
  3x убытков после 24 ч в рынке) — ВНЕДРИТЬ в новую систему
  с адаптацией под её архитектуру (см. п.7.3);
- РЕШЕНО 27.09.2026: геометрический шаг сетки (шаг x множитель^n,
  grid_multiplikator подбирается бинпоиском под целевую
  просадку 40–70% от 5-летнего минимума x2) и мартингейл
  объёма ордера (x1.05, кап max_order_amount = 3x мин. ордера) —
  добавить ОПЦИОНАЛЬНО, управление через ГОЛОВНОЙ СЕРВЕР
  по связке платформа + вид актива: T-Invest — везде ОТКЛЮЧЕНО;
  Bybit — ВКЛЮЧЕНО для спотовых криптовалют (см. п.7.4);
- старое: продление сетки при исчерпании уровней
  (additional_grid_fall_percent 60% равными шагами) — кандидат;
- старое: «Авторазгон» (persent_mode): мин. ордер =
  эквити x % / кол-во ордеров / 2, проверка на
  minOrderAmt x 1.15 биржи — кандидат.

### 7.2. Формулы вывода балансов (Телеграм-сводка старого ПО)

Сводка обновляется in-place (edit_message) каждые 15 сек
(у одного из клиентов 60 сек), при новых сообщениях —
удаление и переотправка. Формулы:
- Equity = get_wallet_balance(UNIFIED).totalEquity, округление
  до 2 знаков (текущие средства по всем монетам);
- Free USDT = get_wallet_balance(UNIFIED, coin=USDT)
  .coin[0].walletBalance, округление до 2 знаков;
- Balance = Free USDT + сумма cumExecValue всех исполненных
  открытых BUY-ордеров всех сеток (из локальной БД) —
  округление до 2 знаков;
- строка по монете: «TICKET | мин.ордер usdt |
  открытых_ордеров/макс_ордеров»;
- в сводке: имя бота, время по Москве, «ПОТЕРЯНА СВЯЗЬ
  С АЛГОРИТМОМ X» при отсутствии данных >120 сек.
- Задача: перенести эти формулы/форматы в Web UI
  (балансы на дашборде, счётчик открытых уровней по каждому
  инструменту, автообновление).

### 7.3. Досрочное закрытие сетки x3 (РЕШЕНО, внедрить)

Перенос из старого ПО с адаптацией: если сетка в рынке
дольше min_working_time (в старом 86400 с = 24 ч) и текущая
нереализованная оценка «прибыль >= profit_loss_ratio x
убытки» (в старом 3), сетка закрывается досрочно
(продажа остатка по рынку), фиксируется событие в журнале
операций. Параметры — в конфиг стратегии.

### 7.4. Геометрический шаг + мартингейл объёма (РЕШЕНО, опционально через головной сервер)

- Конфигурация хранится на ГОЛОВНОМ СЕРВЕРЕ и выдаётся
  клиенту по связке: платформа (брокер) + вид актива
  (акция/спотовая крипта/фьючерс) + при необходимости
  конкретный инструмент.
- Параметры: grid_geometry_enabled (равный/геометрический
  шаг), grid_multiplier bounds для бинпоиска под целевую
  просадку 40–70% от 5-летнего (недельного) минимума x2,
  martingale_enabled, martingale_factor (1.05),
  martingale_max_cap (3x от базового ордера).
- Умолчания: T-Invest — всё ВЫКЛ (текущее поведение:
  равный шаг от исторического диапазона, без мартингейла);
  Bybit спот — ВКЛ (геометрия + мартингейл).
- До появления головного сервера — локальный конфиг
  с теми же полями и умолчаниями (точка включения одна).
