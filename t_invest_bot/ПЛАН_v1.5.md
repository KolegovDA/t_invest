# ПЛАН v1.5 — замечания от 29.09.2026 (после теста 1.4.0-dev)

Контекст: релиз 1.4.0-dev (обновления 13/14) установлен и протестирован.
Замечания разбиты на 3 части: A — клиент «Главная», B — клиент «Настройки»,
C — головной сервер 1.2. Порядок работ: A -> B -> C.

## ЧАСТЬ A. Клиент — вкладка «Главная»

- [x] A1. Баланс показывает не с подключённого счёта — источником баланса
      сделать данные выбранного/активного счёта (синхронно с «Сессиями»).
      Решение: /api/dashboard теперь отдаёт total_equity = сумма капитала
      всех счетов (снапшот баланса счёта, иначе кэш+в позициях), а не
      available_cash только в RUB. /api/dashboard/history строит общий
      график от total_equity (фолбэк на invested+available для старых
      данных), карточка «Главной» показывает total_equity с тем же
      фолбэком.
- [x] A2. При запуске бота и при подключении счёта сверять баланс с реальной
      историей пополнений и операций за 180 дней (загружать у брокера,
      сохранять в БД) — эти данные ложатся в график баланса.
      ВАЖНО (добавлено 30.09.2026): при ПЕРВОМ запуске новой версии
      выполнить бэкфилл для ВСЕХ уже добавленных счетов (включая счета,
      добавленные в старых версиях, по которым локальных снапшотов нет):
      автоматически выгрузить у брокера полную историю счёта и
      восстановить снапшоты балансов за доступный период (до 180 дней),
      чтобы графики показывали реальные балансы, а не только данные
      с момента обновления.
      Решение: BrokerAdapter.get_operations() (Т-Инвест:
      operations.get_operations чанками по 30 дней, только EXECUTED,
      платёж в валюте счёта; Bybit: /v5/account/transaction-log с
      пагинацией cursor). BalanceBackfillService при старте (поток
      balance-backfill-worker, все LIVE-счета) и при подключении нового
      LIVE-счёта (хук в create_trading_account) реконструирует снапшоты
      equity за 180 дней назад от текущего get_portfolio по внешним
      потокам (пополнения/выводы); маркер одноразовости — таблица
      account_backfills (ставится и при пустой истории, НЕ ставится при
      ошибке адаптера — ретрай при следующем старте).
- [x] A3. Убрать кнопки «+ Запустить» и «Сессии» из-под графика.
      Решение: на «Главной» после переработки (A1/A4/A6) таких кнопок уже
      нет — карточка баланса (DashboardCard) рендерит только график,
      переключатели периодов 7D/30D/90D/180D и строку «Последнее
      обновление» (как на эталоне интерфейс\Главная.jpg); ниже идут
      AccountsSummary и «История операций». Проверено по коду: строк
      «Запустить»/«Сессии» на вкладке home нет (остались только во
      вкладке «Сессии», на кнопках запуска в «Счетах» и в нижней
      навигации — их не трогаем).
- [x] A4. Под балансом отображать PnL за всё время работы с учётом прошлой
      истории счёта (см. A2).
      Решение: бэкфилл и воркер снапшотов сохраняют внешние потоки
      (пополнения/выводы) в таблицу broker_cash_flows (дедуп по
      счёт+время+тип+сумма; воркер докачивает новые операции инкрементально
      от последнего потока −1ч). /api/dashboard/history теперь отдаёт
      pnl_total / pnl_total_percent = текущий капитал − первый снапшот
      (get_first_by_currency) − ручные движения − брокер-потоки с того
      момента; потоки также учитываются в кривой графика и pnl_today как
      «movement» (пополнение больше не считается прибылью/скачком).
      Карточка «Главной» показывает вторую строку «P&L за всё время»
      под «за сегодня».
- [x] A5. «История операций» = действия в боте + события по всем счетам:
      пополнения, снятия, прибыль по сделкам, размер комиссии, списанной
      с баланса «Личного кабинета».
      Решение: /api/operations теперь объединяет три источника — журнал
      бота (operations_log, как раньше, без TRAILING; SELL уже содержит
      «прибыль=»), внешние потоки broker_cash_flows (payment>0 ->
      DEPOSIT «пополнение N CUR», иначе WITHDRAWAL «вывод N CUR») и
      комиссии commission_charges (COMMISSION: комиссия/процент/прибыль/
      баланс после списания). Лента сортируется по created_at DESC,
      limit применяется к объединённому списку. Фронт: DEPOSIT/WITHDRAWAL
      уже были в OperationsHistoryCard, добавлена метка COMMISSION
      («Комиссия ЛК»); уведомления по-прежнему только BUY/SELL.
- [x] A6. PnL рядом с балансом всегда 0 — исправить расчёт.
      Решение: PnL за сегодня теперь считается по снапшотам балансов
      (текущий капитал − капитал на начало дня − движения средств за день),
      с фолбэком на прежний расчёт по «прибыль=» из SELL-событий, если
      снапшота на начало дня нет. Работает и для общей «Главной»
      (equity_history_service.build), и по каждому счёту
      (pnl_today_by_account через /api/dashboard accounts_detail).

- [x] B3. Браузерные уведомления не работают на iOS и Android — починить
      (PWA + Web Push, т.к. обычные Notification на мобильных в браузере
      недоступны).
      Референс (статья пользователя, 30.09.2026):
      https://dev.to/u4aew/how-to-set-up-push-notifications-in-safari-on-ios-ki9
      Ключевые требования:
      - iOS: Web Push работает только с Safari 16.4+ И только для PWA,
        добавленной на главный экран (Add to Home Screen); подписка —
        строго из жеста пользователя; нужен manifest + service worker.
      - VAPID-пара: публичный ключ — на клиенте (base64url -> Uint8Array,
        applicationServerKey, userVisibleOnly: true), приватный — на
        сервере (у нас Python: библиотека pywebpush вместо npm web-push).
      - Сервер: POST /subscribe (сохранить subscription в БД),
        отправка — sendNotification(subscription, payload).
      - Клиент: navigator.serviceWorker.ready -> pushManager.getSubscription/
        subscribe; service-worker.js слушает 'push' -> showNotification
        (title, body, icon).
      - Демо: https://push.fancyapp.site/;
        репозиторий: https://github.com/u4aew/react-pwa-push-notifications

      Решение: Web Push (VAPID) поверх pywebpush 2.5.0 + py_vapid
      (pip install в venv; при сборке exe PyInstaller подтянет
      cryptography/http_ece как прямые импорты pywebpush).
      Сервер:
      - notifications/vapid_keys.py: load_or_create_vapid_keys(data_dir) —
        генерирует пару (py_vapid Vapid01.generate_keys, сырой 65-байтный
        публичный ключ X9.62 -> base64url, приватный PEM) и хранит в
        data/webpush_vapid.json (персист между запусками, .env не нужен).
      - infrastructure/sqlite/push_subscription_repository.py: таблица
        push_subscriptions (endpoint PK, subscription_json, created_at);
        save/get_all/delete/count.
      - notifications/webpush_notifier.py: WebPushNotifier (протокол
        notify(message)) — шлёт JSON {title, body} во все подписки;
        404/410 -> подписка удаляется автоматически.
      - notifications/notifier.py: CompositeNotifier (рассылка в
        несколько каналов). api.py: push_notifier теперь всегда
        CompositeNotifier([webpush, +ntfy если задан NTFY_TOPIC]) —
        прежний ntfy-канал сохранён как резерв.
      - Эндпоинты: GET /api/push/vapid-key, POST /api/push/subscribe,
        DELETE /api/push/subscribe?endpoint=..., POST /api/push/test.
      Фронт (PWA):
      - frontend/public: manifest.webmanifest (standalone, иконки
        any+maskable), service-worker.js ('push' -> showNotification,
        'notificationclick' -> focus/openWindow), icons/icon-192|512|180.png
        (сгенерированы Pillow в стиле темы).
      - index.html: link manifest, theme-color, иконки, apple-* мета.
      - main.tsx: регистрация /service-worker.js после load.
      - api.ts: getPushVapidKey/subscribeToPush/unsubscribeFromPush/
        sendTestPush.
      - NotificationSettingsCard.tsx переписана: состояние (поддержка,
        разрешение, подписка), «Включить push-уведомления» — запрос
        разрешения + pushManager.subscribe из жеста пользователя,
        подписка уходит на сервер; «Тестовый push» (POST /api/push/test),
        «Отключить» (unsubscribe + DELETE); подсказка для iPhone про
